# Task #19: Auto-assign id in ralph task add

## What was done
Made `ralph task add` (`taskAdd` in `src/commands/task.ts`) own id assignment so
agents no longer supply ids.

### `src/commands/task.ts`
- `TaskAddOpts`: `dataDir` is now **required** (`string`, was `string?`) and
  added an optional `stdout?: Writer`. All callers (CLI + tests) already pass
  `dataDir`, so no call sites broke.
- In `taskAdd`, after JSON parse and **before** AJV validation:
  - Reserve exactly one id via `reserveTaskIds(opts.dataDir, 1)`, captured into
    a local `assignedId` outside the mutate callback. Reservation failure →
    `ralph task add: <msg>\n` on stderr, exit 1.
  - Inject `assignedId` into the parsed payload (`payload.id = assignedId`),
    overwriting any agent-supplied id. Always ignore supplied ids.
  - Because injection happens before validation, the schema's required `id` is
    always present → no schema relaxation needed.
- On successful mutate, print `assigned id: <n>\n` to stdout so the agent learns
  the id.
- Reservation is done once before the mutate, so a mutate retry reuses the same
  `assignedId` (does not burn a fresh id per attempt).

### `src/commands/run.ts` (executor prompt, DISCOVER AND DOCUMENT block)
- Dropped `id` from the "New tasks need at minimum" list and added a leading
  sentence: "Do NOT supply an id — the CLI assigns one for you and prints it
  ('assigned id: <n>')."

## TDD
Added 3 tests to `test/commands/task.test.ts` `describe('task add')` FIRST,
watched them fail, then implemented. defaultTasks() has ids 1,2 so seed → 3:
- (8d) payload with NO id → reserved id 3 assigned + appended.
- (8e) payload WITH id 999 → overwritten by 3; no task with id 999 remains.
- (8f) stdout receives exactly `assigned id: 3\n`.

## Heads-up for next agents
- `taskAdd` now reserves an id even when the payload later fails validation
  (reservation precedes validation by design). That advances `state.json`'s
  counter, so a rejected `task add` "uses up" an id. This is intentional and
  harmless (ids are non-contiguous-tolerant) but worth knowing.
- `TaskAddOpts.dataDir` is now required — any new caller must pass it.

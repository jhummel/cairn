# Task #21: Rewrite the ID rule in commands/generate-tasks.md

## What was done

Edited `commands/generate-tasks.md` (the source file at the repo root, not the installed copy).

### Two targeted changes:

**1. RULES section (line 149):**
- Old: `Keep task IDs unique and sequential (continue from the highest existing ID if preserving completed tasks)`
- New: `Assign IDs to new tasks only after user approval: run \`ralph task next-id --count <n>\` (where \`n\` = the number of new tasks), then assign the returned IDs sequentially. The command outputs one integer per line. Never reuse archived IDs. Preserve existing completed tasks' IDs and all their metadata unchanged.`

**2. "After receiving" paragraph (line 159):**
- Old: `Once approved, write \`.ralph/tasks.json\` directly using the Write tool — do NOT spawn another agent just to write the file.`
- New: `Once approved: (1) run \`ralph task next-id --count <n>\` (where \`n\` = the number of new tasks) and assign the returned IDs sequentially to the new tasks — the command outputs one integer per line; (2) write \`.ralph/tasks.json\` directly using the Write tool — do NOT spawn another agent just to write the file.`

### Why two places:
The RULES section governs the subagent's behavior during task proposal. The "After receiving" paragraph governs the parent agent's behavior after the user approves. Both needed updating: the rule clarifies that IDs are assigned post-approval (not during proposal), and the approval paragraph describes the exact steps (call `next-id`, assign, then write).

### Output format note:
`ralph task next-id --count 3` outputs integers one per line (e.g., `23\n24\n25`), matching the implementation from task 18. The prompt now references "one integer per line" in both locations.

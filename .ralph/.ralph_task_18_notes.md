# Task #18: `ralph task next-id [--count <n>]` CLI command

## What was done
Added a `next-id` subcommand to the `task` group plus an exported, testable
handler, following the existing `taskAdd`/`taskShow` pattern.

### `src/commands/task.ts`
- New import: `reserveTaskIds` from `../task-counter`.
- New exported handler `taskNextId(opts: TaskNextIdOpts): number`:
  - `TaskNextIdOpts = { count?: number; dataDir: string; stdout?: Writer; stderr?: Writer }`
  - `count` defaults to 1.
  - Validates `Number.isInteger(count) && count >= 1`; on failure writes
    `ralph task next-id: --count must be a positive integer, got <count>\n`
    to stderr and returns exit code 1 — **before** touching state.json
    (so no reservation/state write happens on invalid input).
  - Calls `reserveTaskIds(dataDir, count)` and prints the ids one per line
    (`ids.join('\n') + '\n'`) to stdout, returns 0.
  - Wraps `reserveTaskIds` in try/catch and surfaces errors on stderr → exit 1.
- CLI wiring in `registerTaskCommands`: `task.command('next-id')` with
  `--option('--count <n>', ..., (v) => parseInt(v,10), 1)` (default 1).
  Live command uses the existing `dataDir()` closure (`process.env.RALPH_DATA_DIR`).
  Invalid CLI input like `--count abc` → `parseInt` yields `NaN` → handler
  rejects with exit 1.

### `src/index.ts`
No change needed — `registerTaskCommands(program)` was already wired
(import line 14, call line 182). Confirmed via grep.

## Heads-up for next agents
- `state.json` is the task-id counter file (`{ "nextTaskId": N }`), created
  lazily on first `reserveTaskIds`. It is **untracked** and not in `.gitignore`.
  If a future task (e.g. init, task 20) wants it ignored or seeded explicitly,
  that's a separate concern.
- Live CLI smoke-testing of `next-id` in this sandbox is awkward: the shell has
  `RALPH_DATA_DIR` exported to the repo's `.ralph`, and inline `VAR=val cmd` /
  `env` overrides did not reach the spawned binary — so smoke runs mutate the
  repo's real counter. The unit tests use isolated tmpdirs and are the reliable
  check. (Any stray `state.json` from such smoke runs should be deleted; I removed
  the one my test created.)

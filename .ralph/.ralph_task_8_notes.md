# Task #8 Completion Notes: Plural ready-set selector

## What was done

Added `selectReadyTasks(tasks, completedIds, opts?)` to `src/task-selector.ts`
alongside the existing `selectNextTask` (unchanged).

### Behaviour

- Returns all pending tasks whose dependencies are fully satisfied, using the
  same active+archived complete-id union as `selectNextTask` (lines ~51-54 of
  the original).
- Sorted by priority ascending (lower number = higher priority).
- Capped at `opts.limit` if provided.
- Directory-conflict filtered: after sorting, each candidate whose non-empty
  `directory` is already claimed by a higher-priority batch member is skipped,
  so the returned set never has two tasks writing the same directory.

### In-progress interaction (documented in a code comment)

In-progress tasks are treated as occupying their directories — any pending task
sharing the same non-empty directory as an in-progress task is excluded from the
ready-set before the priority sort even begins. This prevents a parallel wave
from dispatching a new agent into a directory that is already being mutated.
In-progress tasks themselves are never included in the result.

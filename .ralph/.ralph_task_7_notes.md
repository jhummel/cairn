# Task #7 Completion Notes: Concurrency-safe tasks.json writes

## What was done

Made `src/tasks-file.ts` writes safe under concurrent (cross-process) writers.
Each Ralph agent shells `ralph task ...` as a separate OS process, so the
read→modify→write cycle in `mutateTasksFile` was racy and the shared
`${filePath}.tmp` staging file could be clobbered by overlapping writers.

### (a) Per-process unique temp path
- Added `uniqueTmpPath(filePath)` → `${filePath}.tmp.<pid>.<crypto-random-hex>`.
  pid scopes it to a process; the random suffix scopes it within a process, so
  concurrent writers never share — and never clobber — the same staging file.
- `writeTasksFile` now uses `uniqueTmpPath` and **self-cleans**: on any failure
  (writeFileSync or rename) it unlinks its own tmp file in a catch, then rethrows.
  This makes it atomic and leak-free on its own, so callers no longer need to
  manage tmp cleanup. (Note: `writeTasksFile` is also called directly by
  `src/task-archiver.ts` and `src/test-validator.ts` — both benefit, unaffected
  otherwise.)

### (b) Cross-process file lock around the critical section
- Added `acquireLock(lockPath)` using `fs.openSync(path, 'wx')` (O_CREAT|O_EXCL):
  the create fails with EEXIST if another process holds the lock.
  - Bounded retry/backoff: retries every ~15–30ms (jittered) until
    `LOCK_MAX_WAIT_MS` (15s), then throws a clear `TasksFileError` telling the
    user another writer may be stuck and how to recover (remove the lockfile).
  - Stale-lock breaking: a lock older than `LOCK_STALE_MS` (60s) is assumed
    orphaned (holder crashed) and removed, so the file can never deadlock
    permanently. Lock content is `{pid, ts}` (best-effort metadata).
  - `sleepSync` uses `Atomics.wait` on a SharedArrayBuffer for a non-spinning
    synchronous sleep (these are sync functions).
- `mutateTasksFile` now acquires the lock, runs read→fn→write→snapshot entirely
  inside it, and releases (closeSync + unlink lockPath) in a `finally`.
  The existing snapshot-after-write behavior is preserved (now inside the lock,
  so the snapshot is consistent with the write).

# Task #16: Extract shared file-lock helper into src/file-lock.ts

## What was done
- Created `src/file-lock.ts` holding the cross-process advisory-lock machinery moved out of `src/tasks-file.ts` (formerly lines 189–240):
  - `acquireLock(lockPath)` — exported
  - `sleepSync(ms)` — exported
  - `LOCK_RETRY_MS` / `LOCK_MAX_WAIT_MS` / `LOCK_STALE_MS` constants (module-private)
  - `FileLockError` class — exported. Defined locally to avoid file-lock.ts depending on tasks-file.ts. The lock-timeout message text is preserved verbatim ("Could not acquire tasks-file lock at ... within 15000ms; ...").
- Behavior preserved exactly: O_EXCL ('wx') open, best-effort pid/ts metadata write, stale-lock break via `mtimeMs > LOCK_STALE_MS`, bounded retry/backoff with jitter, returns the open fd.
- Refactored `src/tasks-file.ts`: added `import { acquireLock } from './file-lock'`, removed the now-duplicated `sleepSync`/`acquireLock`/constants. `mutateTasksFile` calls the imported `acquireLock` unchanged (signature `acquireLock(lockPath)`).

## Error type change (intentional, per task)
The lock-timeout error was previously thrown as `TasksFileError`; it is now `FileLockError`. Message text is identical. No test or caller asserted on the timeout error *type* (verified via grep of tasks-file.test.ts — only checks lockfile unlink behavior, not error class).

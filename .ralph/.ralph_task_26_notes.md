# Task #26: Field-preserving state.json I/O + round counter

## What changed
`src/task-counter.ts`:
- `CounterState` is now an open-ended type (`{ nextTaskId?, round?, [key]: unknown }`) instead of `{ nextTaskId: number }`, so unknown fields survive round-trips.
- `readState()` now returns the raw parsed object (spread), preserving every field. `nextTaskId` is still validated as a finite number — if invalid it is dropped but sibling fields (e.g. `round`) are kept. Returns `null` only when the file is missing or not a JSON object.
- `reserveTaskIds()` writes `{ ...existing, nextTaskId: start + count }` instead of `{ nextTaskId }` — this is the clobber fix. `start` now guards on `typeof existing.nextTaskId === 'number'` before falling back to `seedNextId`.
- Added `getRound(dataDir)`: pure read. Returns the `round` field, or `1` if file/field absent or non-finite. Never creates or mutates state.json.
- Added `bumpRound(dataDir)`: atomic read→increment→write under the same `state.json.lock` (acquireLock) + temp-file-rename machinery as reserveTaskIds. Absent round === 1, so bumping a file without a round writes `round: 2`. Preserves nextTaskId and all other fields. Returns the new round value.
- Both `getRound` and `bumpRound` exported.

## Tests (test/task-counter.test.ts)

# Task #31 — src/brand.ts + dual-read discovery and config

## What was built

**`src/brand.ts` (new)**
- `BRAND` — frozen: `name: 'cairn'`, `displayName: 'Cairn'`, `dataDir: '.cairn'`, `configFile: 'cairn.json'`, `envPrefix: 'CAIRN_'`, `tempPrefix: '.cairn_'`, `socket: '/tmp/cairn-tts.sock'`.
- `LEGACY` — frozen: `name: 'ralph'`, `displayName: 'Ralph'`, `dataDir: '.ralph'`, `configFile: 'ralph.json'`. Read-only fallback surface; nothing writes these.
- `warnLegacyOnce(key, message)` — stderr, at most once per key per process, returns whether it emitted. stderr (not stdout) because commands like `ralph task next-id` print machine-readable stdout.
- `resetLegacyWarnings()` — re-arms the warnings; exists for tests.

**`src/utils.ts`**
- New `findDataDir(projectRoot)`: existing `.cairn/` → existing `.ralph/` → default `.cairn/`. **This is the function every later task should use to resolve a data path.**
- `findProjectRoot()` now checks *both* names at *every* level of the upward walk (via the private `dataDirNameAt()`), so the *nearest* project wins regardless of layout. A parent on `.cairn/` no longer shadows a child on `.ralph/`.
- Non-directory `.cairn` entries are ignored (`statSync(...).isDirectory()` in try/catch), so a stray `.cairn` file doesn't mask a real `.ralph/`.

**`src/config.ts`**
- New `findConfigFile(projectRoot)`: existing `cairn.json` → existing `ralph.json` → default `cairn.json`.
- `loadConfig()` now resolves through `findConfigFile()` instead of hardcoding `ralph.json`. Behaviour otherwise unchanged (all pre-existing config tests pass untouched).

Legacy warning keys are `'data-dir'` and `'config-file'` — one warning each per process, no matter how many call sites hit them.

## STANDING RULE (carry into every later task in this round)

`BRAND.dataDir` / `BRAND.configFile` are for **CREATING** paths, never for **RESOLVING** them. Anything pointing at data that should already exist must come from `findDataDir()` / `findConfigFile()`. Five other projects on this machine still use `.ralph/`; hardcoding `BRAND.dataDir` at a read site silently points them at a nonexistent `.cairn/`.

Known call sites that still hardcode `'.ralph'` and must be converted by later tasks (NOT touched here — this task was scoped to rename nothing else):
- `src/index.ts:36` — `const dataDir = join(projectRoot, '.ralph')`
- `src/index.ts:127` — `join(projectRoot, '.ralph', 'tasks.completed.json')`
- `src/post-task-reviewer.ts:137` — allowlist rule `/${projectRoot}/.ralph/reviews/**`
- `src/commands/init.ts` — creates `.ralph/` (creation site, so `BRAND.dataDir` is correct there, but it must not clobber an existing legacy dir)
- `src/commands/edit.ts:17` — `join(projectRoot, 'ralph.json')` → should use `findConfigFile()`
- `src/commands/init.ts:185` — writes `ralph.json` (creation site → `BRAND.configFile`)

`RALPH_PROJECT_ROOT` and the `RALPH_*` env vars in `setConfigEnvVars()` were deliberately left alone — that's the `envPrefix` task.

## Tests

`test/brand.test.ts` (new), plus appended blocks in `test/utils.test.ts` and `test/config.test.ts`. Per the task, they assert on literal `'.cairn'` / `'cairn.json'` strings rather than importing `BRAND`, so a wrong value in brand.ts fails loudly. Coverage: preference order, legacy fallback, nearest-root-wins, non-directory `.cairn`, warn-exactly-once, and no-warn on the modern layout.

Suites that override `console.error` must call `resetLegacyWarnings()` in `beforeEach` — otherwise an earlier test consumes the one-time warning and the assertion sees zero output.

## Build health fix (incidental)

The failing health check was `ralph.json`'s `healthCheck` command: `bun build src/index.ts --outfile /tmp/cairn-healthcheck` defaults to the browser target and dies on `readline` and other Node builtins imported by `src/index.ts`. Added `--target=bun`. Both `bun run build` (which uses `--compile`, and so was never broken) and the health check now succeed. Noted in CLAUDE.md.
